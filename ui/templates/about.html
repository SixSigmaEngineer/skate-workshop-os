About SKATE

You Can’t Vibe Code Personality.

Software can be generated. Trust, judgment, curiosity, and the way a great facilitator reads a room cannot. SKATE preserves that human context—then gives it structure, memory, and momentum.

Core idea

SKATE turns markdown into memory.

SKATE, Scalable Knowledge Architecture & Technology Engine, is a local-first memory and workshop-synthesis system. Every note is a plain markdown file with structured metadata — readable by you, searchable by the app, traversable in the mind map, and available as grounded context for SKATE’s agents. No database and no proprietary note format: the vault is a folder on your disk that you can open in any text editor (including Obsidian) or commit to Git.

How it works

Capture → Tag → Connect → Synthesize. Manual notes and meeting transcripts preserve what happened; Spotter uses that session memory to support the facilitator. A note can use one of 14 object types, including observation, pain, insight, decision, quote, question, action item, and recommendation. Notes can also carry themes, a workshop session, and typed relationships to other notes: supports, contradicts, causes, leads_to, references, and similar_to. The Grind builds a graph from those links, and a session-scoped synthesis pass produces design-thinking outputs — top pain points, How-Might-We prompts, and solution starters — exportable to Excel.

The Lineup

The Lineup turns captured action into visible follow-through. Action Items can be flexible or tied to a workshop session, assigned an owner and due date, and checked off as Landed. Daily, weekday, weekly, and monthly Standard Work returns on a predictable cadence. SKATE also finds #A bullets inside ordinary notes and lets you promote them into trackable Action Items while preserving a relationship back to the source note.

The memory tech (and why it holds up)

Retrieval is hybrid: 60% semantic embedding similarity blended with 40% normalized keyword scoring when embeddings are available. The semantic side retrieves by meaning — a question about “pricing” can find notes about “cost” — using an optional backend auto-detected at runtime: local Ollama with nomic-embed-text, local fastembed, or OpenAI embeddings when an OpenAI key is configured. The keyword side keeps exact-match precision for names and project terminology. If no embedding backend is available, SKATE degrades gracefully to keyword-only retrieval.

Embeddings are cached on disk by content hash, so unchanged notes do not need to be embedded again. There is deliberately no vector database: retrieval calculates similarity over the locally cached vectors. Prompts stay token-bounded — agents receive a limited set of the most relevant note summaries rather than the entire vault.

Unlike agent-memory frameworks built on opaque vector stores, SKATE's memory is human-readable and human-curated — a vault you can read, edit, and hand to a client.

The mind map (The Grind)

The Grind is a force-directed 3D/2D graph rendered with a hand-written WebGL engine. Every note is a node, colored by its object type (pains red, insights purple, recommendations green, and so on). Two kinds of rails connect them: relationship rails — the explicit typed links stored in each note’s metadata — and theme rails, which connect notes that share a theme. Degree caps keep highly reused themes from overwhelming the map. A physics layout pulls connected notes together and pushes unrelated ones apart, making clusters useful signals for a facilitator to investigate. Inspect nodes, filter the rails or session, then run the synthesis pass to produce pain points, How-Might-We prompts, and solution starters grounded in the selected session’s active notes.

Voice and transcription

When you start listening, Spotter Live captures the selected microphone and writes a timestamped markdown transcript. The primary cloud path uses OpenAI GPT-Realtime Whisper for streaming captions and GPT-Realtime mini for Spotter’s spoken responses, using the same OpenAI key as the rest of SKATE. Choose Local Whisper when audio must remain on this computer, or optional ElevenLabs Scribe when speaker diarization is required. Local Whisper and OpenAI Realtime do not identify speakers; ElevenLabs can display speaker labels when the service returns them. SKATE’s local server is bound to 127.0.0.1, and API credentials remain on the Python side of the desktop application rather than entering page JavaScript.

How SKATE is built

SKATE was created for OrionHackathon 2026 on Devpost in the Productivity & Enterprise Solutions track. AI-assisted development served as an active engineering partner throughout the build: translating the product vision into a working application, shaping the local-first architecture, implementing and debugging features, refining the interface, generating realistic demonstration data, and helping test the complete workflow.

The running application uses the OpenAI Responses API with explicit GPT-5.6 routing. The GRIND uses the General GPT-5.6 model and reasoning level selected in Settings for its evidence-heavy task: reading active workshop evidence, finding patterns and tensions, and producing traceable pain points, How-Might-We framing, and solution starters. Spotter can use a separate, lower-latency GPT-5.6 configuration for responsive workshop coaching. OpenRouter and local LLM routing are intentionally excluded from this build so the demonstrated reasoning path is unambiguous.

This application is a direct output of that human-and-agent collaboration. AI accelerated the distance from idea to implementation; the purpose, facilitation philosophy, product judgment, and commitment to helping people and organizations came from its creator. That is the meaning behind the headline: you can’t vibe code personality.

The stack

  • Python + FastAPI + pywebview: local application server inside a native desktop window
  • Markdown vault: durable, portable, Obsidian-compatible storage
  • Hybrid retrieval: local embeddings (Ollama / fastembed) + weighted keyword scoring, disk-cached
  • Hand-written WebGL: The Grind's 3D graph renderer — no framework, no build step
  • SKATE boards: customizable visual signals for the team

Skateboards
